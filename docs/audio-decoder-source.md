# Selected audio decoder and seek windows (D70)

2026-10-13. The user's **Proceed** authorizes this native increment after
[D69's merged source foundations](audio-source-inventory.md). It implements a
private optional decoder adapter in `src/audio_decoder_source.*`, built as
`sap2_audio_decoder` alongside the existing optional codec probe. The shipping
playback target, experimental ABI, CLI delivery values and published `ci.207`
package do not link/load it yet. HLS audio generation is the following increment.

## Identity and backend

Open snapshots the host size once, probes the native unfiltered MP4/MKV inventory,
and applies D69's deterministic selection before asking whether the chosen codec
can decode. Missing/disabled/non-audio identities, ambiguous selection, protected
entries and unsupported codecs fail explicitly; no alternate audio is chosen.

MOV's AVStream.id retains the original unsigned 32-bit tkhd identity. The sample
entry's `esds` objectTypeIndication distinguishes AAC from DTS inside `mp4a`;
fourcc alone is insufficient. The helper reuses the native bounded descriptor
reader and does not change existing remux selection. Matroska's original
TrackNumber is exported as full unsigned hexadecimal metadata by the small
[documented FFmpeg overlay patch](dependencies.md#native-decoder-adapter-d70).
File tags, including case variants, cannot overwrite that reserved key. A backend
without this bridge is refused for Matroska; stream order, title or language is
never used as an identity fallback. The selected native/backend codec must agree.

The adapter uses the existing pinned FFmpeg 9.0.2 dynamic LGPL profile, verifies
the actual four-library license/configuration and network-disabled settings,
and discards unselected streams before decoder analysis. It opens only custom
host AVIO; no path, URL, external process or credentials are passed to FFmpeg.

## Presentation and seeking

`read_window(first_sample, count, context)` returns owned interleaved float PCM
at 48 kHz, preserving the source's native channel mask/count. This increment
does not downmix that PCM or encode a production AAC rendition. Requests use
the audible, edited presentation clock rather than raw container time.

Every window seeks to at least one second before its target, or the larger
Matroska SeekPreRoll, flushes the decoder and creates a fresh resampler. MOV
seeking can include negative AAC priming packets. Decoder initial_padding is
cleared because demuxed PTS and packet skip/discard information already describe
the presentation corrections. MP4 edits and Matroska CodecDelay are applied by
the pinned demuxer; D69's raw-container planners are not applied again. Initial
edit silence is zero-filled; decoded samples after actual EOF are omitted.

For resampling, the epoch begins at a rational phase aligned with presentation
sample zero. Up to one input/output phase period of dummy history is processed
before real input; decoder/resampler preroll discards that history before output.
This avoids different fractional phases when a 44.1 kHz stream is revisited.

The returned timestamp precision is the container clock's tick rounded upward
to 48 kHz samples: the fixtures demonstrate one sample for 48 kHz MP4, two for
44.1 kHz MP4 and 48 for millisecond Matroska. A coarse Matroska timestamp is not
sample-exact seek evidence. Timestamp gaps beyond that quantum, nonfinite PCM,
or channel/rate/sample-format changes within or across seek epochs are refused.
This is a bounded decoded-window contract, not independent AAC/HLS segment
priming, padding, joining or receiver synchronization proof.

## Ownership and bounds

The object retains copied callbacks and borrows their external immutable storage
for its lifetime. Calls on one object are serialized. Each operation borrows the
caller's valid MediaReadContext until return, preserving its absolute deadline
and both cancellation flags. No background work/callback after return occurs.
Callback exceptions are caught inside FFmpeg's C callbacks and rethrown on the
C++ side. Failed windows invalidate the object; the caller discards it. Invalid
request arguments are refused before I/O and do not invalidate a working object.

Engineering bounds: source <=1 TiB; <=128 native/decoder streams; <=256 MiB
requested bytes and 1,048,576 read callbacks per decoder operation; read capacity
<=32 KiB (native inventory keeps its own <=64 KiB/read and metadata budgets);
windows <=10 seconds within a <=7-day presentation; <=20 seconds decoded input
per window; 1..8 known native channels, 8..192 kHz input, and resampling phase
period <=8192 input samples. Complex MP4 edits, multiple selected sample
descriptions and altered Matroska track clocks remain unsupported. These are
sender resource limits, not receiver limits.

## Validation and remaining gates

Original three-second H.264/channel-tone MP4/MKV fixtures are generated by
`tools/audio-codec-spike/generate_decoder_fixtures.py`. Their configuration,
encoder arguments, authored identities/clocks/edits and hashes are recorded in
[provenance](../tools/audio-codec-spike/fixtures/decoder/provenance.json).
They are actual compressed samples, separate from D69's synthetic index payloads.

Desktop CTest passes both `audio_decoder_source` and the preserved D68
`audio_codec_probe`. Cases cover AAC/AC-3/E-AC-3/DTS-core 5.1 in MP4 and
AC-3/E-AC-3/DTS-core 5.1 in Matroska with AAC commentary; reordered tracks,
explicit/default selection, unknown/protected/disabled/invalid selection without
fallback, 64-bit Matroska identity and reserved-key spoofing. Late/backward/forward
windows after EOF are compared with continuous compressed decoding within the
declared clock quantum. Independent edited/unedited and delayed/undelayed file
comparisons check 250 ms initial silence, a 500 ms media offset and 20 ms
CodecDelay exactly once. 44.1 kHz resampling, changing AC-3 layout, short reads,
size-once, cancellation/deadline, invalid/throwing callbacks, request bounds,
failure invalidation and EOF tail behavior also pass.

Baseline static/shared CTest, actual PR-head CI and UWP compilation/import
inspection are recorded in [the handoff](HANDOFF.md#0-resume-here). UWP validation
here is compilation and binary inspection; the new adapter is not wired into
the packaged probe's C interface and has no new AppContainer runtime observation.
No receiver run or package publication is added. DTS-HD and dependent E-AC-3
substream fixtures, long/real-movie performance and additional codec/layout
profiles remain unvalidated. Speaker transport and discrete surround output
remain deferred for unavailable test hardware.
